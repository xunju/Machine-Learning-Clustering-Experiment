# Group Discovery 实验方案设计

## 1. 数据集说明

本实验使用 students003 数据集。

数据文件路径为：
```
/root/autodl-tmp/TrajectoryData_students003/students003.txt
```
数据文件包含四列：

| 字段名 | 含义 |
|---|---|
| time_step | 时间步或视频帧编号 |
| ID | 行人编号 |
| X | 行人在二维平面中的横坐标 |
| Y | 行人在二维平面中的纵坐标 |

本实验以 time_step 为单位，对每一帧中的所有行人坐标点分别进行聚类。

## 2. 实验任务定义

本实验目标是根据视频中每一帧的行人轨迹坐标点，自动发现行人组。

对于某一帧 t，其输入是该帧中所有行人的二维坐标点。聚类算法根据这些点之间的空间距离关系，将位置接近的行人划分为同一组。

后续可视化时，不同颜色表示不同的行人组。

## 3. 实验总体流程

本实验采用逐帧聚类流程：

1. 读取 students003 数据；
2. 按 time_step 对数据分组；
3. 提取每一帧中的 X、Y 坐标；
4. 对当前帧坐标点进行聚类；
5. 为每个行人分配 group_id；
6. 保存逐帧聚类结果；
7. 绘制每一帧的聚类可视化图；
8. 将所有帧图像合成为 MP4 视频。

需要注意的是，本实验不是将所有帧中的轨迹点混合在一起聚类，而是对每一帧独立聚类。这与题目中“对视频中每一帧的行人轨迹坐标点进行聚类”的要求一致。

## 4. 对比聚类方法

为了增强实验完整性，本文计划比较以下四类无监督聚类方法。

### 4.1 KMeans 聚类

KMeans 假设数据可以被划分为预先设定数量的簇。该方法简单、稳定、速度快，适合作为基线方法。

候选参数：

- n_clusters = 2
- n_clusters = 3
- n_clusters = 4

不足之处是需要提前指定聚类数量，不能完全自动决定行人组数量。

### 4.2 DBSCAN 聚类

DBSCAN 是一种基于密度的聚类方法，可以根据样本点空间密度自动发现簇结构，并能够识别噪声点。

候选参数：

- eps = 0.8, 1.0, 1.2, 1.5
- min_samples = 2, 3

DBSCAN 的优点是不需要预先指定簇数量，更符合“自动发现行人组”的任务要求。其不足是对 eps 和 min_samples 参数较为敏感。

### 4.3 层次聚类

层次聚类根据样本之间的距离逐步合并或划分簇，适合分析二维点集中的空间层次结构。

候选参数：

- n_clusters = 2
- n_clusters = 3
- n_clusters = 4

该方法结果直观，但通常也需要指定最终簇数量。

### 4.4 高斯混合模型 GMM

GMM 假设数据由多个高斯分布混合生成，并通过概率模型对样本进行聚类。

候选参数：

- n_components = 2
- n_components = 3
- n_components = 4

GMM 可以给出概率意义上的软聚类结果，但同样需要预先指定成分数量，并且对初始化较敏感。

## 5. 最终聚类策略

最终视频生成阶段采用 DBSCAN + KMeans 兜底策略。

具体流程如下：

1. 对每一帧行人坐标点优先使用 DBSCAN 聚类；
2. 统计 DBSCAN 得到的有效簇数量，其中噪声点标签 -1 不计入有效簇；
3. 如果有效簇数量大于等于 2，则保留 DBSCAN 聚类结果；
4. 如果有效簇数量小于 2，则使用 KMeans(n_clusters=2) 重新聚类；
5. 通过该策略保证每一帧至少显示 2 个行人组；
6. 对每一帧绘制不同颜色的聚类结果；
7. 最终将逐帧图像合成为 MP4 视频。

该策略的设计理由是：DBSCAN 能够较自然地根据空间密度自动发现行人组，而 KMeans 兜底可以避免 DBSCAN 在个别帧中只得到一个簇或大量噪声点，从而满足“每帧至少显示 2 组行人”的要求。

## 6. 无监督实验评价方式

由于 students003 数据中没有提供真实行人组标签，因此不应使用准确率、召回率、F1 值等监督学习指标。

本实验将从以下角度评价聚类结果：

1. 每帧发现的聚类组数量；
2. 是否每帧至少包含 2 个行人组；
3. DBSCAN 的噪声点比例；
4. 不同聚类方法的平均运行时间；
5. 聚类结果在连续帧之间的稳定性；
6. 可视化结果是否能够直观反映行人空间分组。
