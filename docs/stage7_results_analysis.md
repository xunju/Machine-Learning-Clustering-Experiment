# 第七阶段：实验结果分析

## 1. 数据集检查结果分析

students003 数据集共有 17953 条轨迹记录，覆盖 541 个 time_step，共出现 434 个不同的行人 ID。每条记录包含 time_step、ID、X、Y 四个字段，分别表示时间步、行人编号和二维坐标。数据时间步从 0 到 5400，间隔固定为 10，不存在缺失时间步。每帧行人数最少为 13，最多为 52，平均约为 33.18，且不存在缺失值和同一帧同一 ID 的重复记录。

因此，该数据集能够满足逐帧行人轨迹点聚类和可视化视频生成的基本要求。

## 2. A 类基础单帧空间聚类结果分析

A 类方法仅使用每一帧的 X、Y 坐标进行聚类，目的是建立基础 baseline。实验中对比了 KMeans、DBSCAN、Agglomerative Clustering 和 GMM 四种方法。

KMeans、Agglomerative Clustering 和 GMM 均设置聚类数为 3，因此所有帧均输出 3 个聚类组，结果稳定且能够满足每帧至少 2 组的要求。但这类固定簇数方法不能根据不同帧中行人分布的变化自动调整组数。

DBSCAN 不需要预先指定簇数量，能够根据空间密度自动发现不同数量的行人组。A 类 DBSCAN 平均每帧得到约 4.65 个有效簇，平均噪声比例约为 7.7%，所有帧均满足至少 2 组的要求。该结果说明，基于空间密度的 DBSCAN 更符合“自动发现行人组”的任务目标。

然而，A 类方法只利用当前帧空间位置，无法判断行人是否具有相似运动趋势，也无法区分“短暂靠近”和“持续同行”的情况。因此，A 类方法适合作为 baseline，但不足以充分表达 Group Discovery 中的时序关系。

## 3. B 类运动特征增强结果分析

B 类方法在 X、Y 坐标基础上加入运动信息，包括瞬时速度、滑动窗口速度、指数衰减动量和运动方向近似朝向。

初始实验中，B 类方法使用 eps=0.8、position_weight=1.0、motion_weight=1.0。结果显示，加入运动特征后平均簇数明显升高，噪声比例也明显增加。例如，window_velocity 初始版本平均簇数约为 7.65，平均噪声比例约为 31.7%；momentum 初始版本平均簇数约为 7.81，平均噪声比例约为 30.7%。这说明运动特征能够增强对不同行人运动差异的区分能力，但如果运动特征权重过高，会导致过度切分和噪声点比例上升。

为缓解这一问题，本文进一步调整参数，将 eps 设置为 1.0，并将 motion_weight 降低为 0.5。改进后的 window_velocity 方法平均簇数下降到约 3.95，平均噪声比例下降到约 10.7%；改进后的 momentum 方法平均簇数约为 4.01，平均噪声比例约为 10.3%。这说明运动特征应作为空间位置特征的辅助信息，而不宜在距离度量中占据过高权重。

综合可解释性和实验结果，本文将 window_velocity, eps=1.0, motion_weight=0.5 作为 B 类代表方法。

## 4. C 类时序关系建模结果分析

C 类方法不再只为单个行人构造特征，而是直接建模行人与行人之间的关系。本文实现了持续邻近关系层次聚类、关系图连通分量方法和 Pairwise Affinity 谱聚类。

temporal_agglomerative 和 affinity_spectral 均设置 n_clusters=3，因此结果稳定，但不能自动调整组数。relation_graph 方法通过距离阈值和速度阈值判断两名行人之间是否连边，再将连通分量作为行人组，能够自动形成不同数量的组，更贴近 Group Discovery 的任务设定。

实验表明，relation_graph 对参数较敏感。当 dist_threshold=1.2、vel_threshold=0.08 时，平均每帧形成约 15.71 个组，明显过度切分；当阈值放宽到 dist_threshold=2.0、vel_threshold=0.15 时，平均簇数下降到约 7.81；进一步放宽到 dist_threshold=2.5、vel_threshold=0.20 后，平均簇数下降到约 4.86，簇数量波动也更合理。

因此，本文选择 relation_graph, dist_threshold=2.5, vel_threshold=0.20 作为 C 类代表方法。该方法能够表达持续邻近关系，但也存在连通分量传播导致过度合并的风险。

## 5. D 类参数分析与稳定性分析

由于数据没有真实行人组标签，本文不使用准确率、召回率和 F1 等监督指标，而是采用无监督统计指标和连续帧稳定性指标进行评价。

从平均簇数和噪声比例看，A 类 DBSCAN 平均簇数约为 4.65，噪声比例约为 7.7%；B 类初始运动特征方法平均簇数和噪声比例均偏高；B 类改进参数后，window_velocity 和 momentum 方法的平均簇数与 A 类 DBSCAN 接近，同时保留了运动信息；C 类 relation_graph 在合适阈值下平均簇数约为 4.86，但对阈值较敏感。

从连续帧稳定性看，B 类改进方案比初始 B 类方案更稳定。其中 momentum_eps1.0_mw0.5 的 mean_cluster_count_change 约为 0.493，window_velocity_eps1.0_mw0.5 约为 0.574，均优于 A 类 DBSCAN 的 0.704。这说明合理调节运动特征权重后，运动信息有助于提高连续帧结果稳定性。

## 6. Final 最终方法选择理由

综合平均簇数、噪声比例、连续帧稳定性、可解释性和视频展示效果，本文最终选择 B 类中的 window_velocity 改进方案作为 Final 方法。最终方法使用 X、Y、window_vx、window_vy 作为特征，采用 DBSCAN + KMeans fallback 策略。

最终参数为：

| 参数 | 取值 |
|---|---:|
| eps | 1.0 |
| min_samples | 2 |
| window_size | 5 |
| position_weight | 1.0 |
| motion_weight | 0.5 |

最终结果覆盖全部 541 帧，平均每帧得到约 3.95 个行人组，平均噪声比例约为 10.7%，fallback 帧数为 7，占比约为 1.29%，所有帧均满足至少 2 个行人组的要求。最终视频中不同颜色表示不同组，点旁标注行人 ID，能够较完整地展示 students003 数据中的逐帧行人组发现结果。

## 7. 方法不足与改进方向

本文方法仍存在以下不足：

1. 数据没有真实行人组标签，因此评价主要依赖无监督统计指标和可视化判断，无法计算严格的监督准确率。
2. DBSCAN 对 eps 和 min_samples 较敏感，不同参数会影响簇数量和噪声比例。
3. 滑动窗口速度只能近似表达短时运动趋势，不能完全判断真实社交关系。
4. 关系图方法能够表达持续邻近关系，但容易受到阈值影响，可能出现过度切分或过度合并。
5. 视频中的 visual_group_id 只用于颜色稳定显示，不改变原始聚类结果，也不能完全解决跨帧组身份跟踪问题。

后续可以进一步引入更稳定的跨帧组匹配方法、图社区发现算法、轨迹级聚类方法，或者在有人工标注的情况下引入监督评价指标，从而更准确地评估行人组发现效果。
